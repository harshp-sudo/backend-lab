Real-Time & Async Communication

To learn when dinner is ready, you can keep a two-way phone call open, listen to a one-way announcement channel, or ask the waiter to wait until there is news before replying. Each keeps you informed with different resource and recovery costs.

WebSockets, SSE and long polling change how clients wait for updates. The application still owns authentication, replay, duplicates, ordering and reconnect gaps. A live connection is not a durable event log.

🗺️ Roadmap

Read this as a map of learning choices, not a claim that every child is a required technical dependency.

Suggested reading guide

Start with WebSockets when both parties need frequent independent messages. Compare SSE when updates primarily flow toward the browser.

Study Long Polling as a held-request fallback with explicit timeouts and cursors. For every choice sketch disconnect, replay and expired-history behavior, then connect to backend Event-Driven Architecture for publication ownership.
