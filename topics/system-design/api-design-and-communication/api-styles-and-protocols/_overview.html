API Styles & Protocols

Ordering from a menu, filling a custom plate, calling a named kitchen station and mailing a formally structured order are different ways to ask for work. None makes the kitchen automatically faster or safer. Choose the agreement that fits the diners and the work.

These four lessons compare resource-oriented HTTP, a client-selected graph, typed RPC and structured XML messaging. Follow one example through its contract, execution, errors and evolution; serialization format alone is not architecture.

🗺️ Roadmap

Read this as a map of learning choices, not a claim that every child is a required technical dependency.

Suggested reading guide

Begin with REST API Design for HTTP resource and method semantics. Then use GraphQL to examine flexible selection and resolver costs.

Study gRPC for typed service communication, deadlines and streams. Use SOAP to understand explicit envelopes, WSDL and partner interoperability. Compare actual client constraints rather than ranking formats.
