Common Web & API Vulnerabilities

A clerk should treat a customer’s note as data, not as a new office instruction. A display should show a note without executing it. A signed-in browser should not accept a stranger’s instruction merely because it carries the visitor’s pass.

Trace the actual source, interpretation context and effect: query construction, rendered/DOM content or a state-changing browser request. Each needs its own appropriate defense.
