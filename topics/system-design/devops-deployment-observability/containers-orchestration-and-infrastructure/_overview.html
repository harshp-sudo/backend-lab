Containers, Orchestration & Infrastructure

A traveling fair packs equipment in labeled boxes, allocates stalls, replaces broken booths and adds staffed stalls when demand grows. A box does not manage the fair, and asking for another booth does not create land or electricity. Separate packaging, coordination and physical capacity.

Docker explains images and running containers. Container Orchestration describes the general responsibilities; Kubernetes makes those control loops concrete. Infrastructure as Code manages versioned infrastructure ownership, and HPA changes desired workload replicas using measured signals.

Suggested reading guide

Begin with image/process and resource boundaries, then trace desired state through scheduling to a ready service. Keep infrastructure state and application state distinct. Learn autoscaling only after naming the metric, resource request and the capacity that can actually run new Pods.

Explore this branch

  • Docker & Containerization

    Image versus running container, layers/build context, process/filesystem/network isolation, volumes and limits; reproducibility, image provenance, least privilege and shared-kernel boundaries.

  • Kubernetes

    Concrete desired-state control plane, scheduling, Pods/controllers, Services/configuration/storage and lifecycle; trace a deployment and diagnose pending/unready work with explicit ownership boundaries.

  • Container Orchestration

    Platform-independent scheduling, reconciliation, placement, service discovery, rollout, resource and failure-domain responsibilities; compare orchestration choices and when simpler hosting suffices.

  • Infrastructure as Code

    Versioned desired infrastructure, preview/apply lifecycle, state and locking, drift, dependency ordering, safe concurrent changes, secrets, imports and recovery from partial application.

  • Horizontal Pod Autoscaling

    Kubernetes replica control loop, resource/custom/external metrics, utilization/request assumptions, bounds and stabilization, startup lag and missing metrics; distinguish Pod scaling from node capacity.
