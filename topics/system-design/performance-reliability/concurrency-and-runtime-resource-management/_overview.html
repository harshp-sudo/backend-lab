Concurrency & Runtime Resource Management

A small workshop has a notice board, workers, tools and shelves. Writing more jobs on the board does not create workers or shelf space. Good scheduling means somebody owns every job, queues stay bounded and measurements reveal which resource is actually busy.

Follow asynchronous ownership, bounded workers and non-blocking I/O before measuring retained memory and CPU use. Name the runtime when a scheduling or garbage-collection detail matters; a promise is not a durable queue and a thread is not extra processor capacity.

Suggested reading guide

Start with the execution model, then follow the suspected bottleneck to memory or CPU evidence. Compare wait time with useful work, change one mechanism and repeat a comparable measurement rather than assuming more concurrency helps.

Explore this branch

  • Asynchronous Processing

    Trace scheduling, completion, ownership, cancellation and error propagation; distinguish concurrency, CPU parallelism and durable job handoff; bound pending work and propagate deadlines/context.

  • Thread Pools

    Budget workers and queue capacity for CPU- versus blocking-I/O work; diagnose saturation, nested waits, starvation and oversubscription; compare rejection, queuing and isolation policies under a named runtime.

  • Non-Blocking I/O

    Explain readiness/completion and event-loop scheduling; identify blocking calls or CPU work on the loop, bounded buffers and slow peers; compare blocking worker and non-blocking execution costs.

  • Memory Management

    Follow allocation, ownership, reachability and release; distinguish retention leaks, allocation pressure, heap versus process/container memory, and runtime-specific collection behavior; bound queues/caches and verify fixes.

  • CPU Profiling

    Choose sampling or instrumentation, interpret representative call stacks/flame graphs and CPU versus elapsed time, account for contention, quotas, symbols/JIT and overhead; verify a hotspot fix with comparable measurements.

Choose one bottleneck, explain the evidence that identifies it and name the assumption that would change your decision. Opening this roadmap does not mark its lessons mastered.
