Performance & Reliability

A restaurant stays useful when the kitchen, serving staff and waiting room fit together. Faster chopping does not help when every table is waiting for one oven. First locate where work waits, then change that resource and check whether hungry customers actually get served sooner.

This branch follows a request from database work through runtime ownership, surge response and production lifecycle. Treat performance as a measurable user outcome and reliability as preserving useful, truthful behavior under constrained resources.

Suggested reading guide

Begin with data-access diagnosis, then runtime scheduling and resource evidence. Use traffic testing to challenge the model and production observability to verify it. These are complementary paths, not a requirement to optimize everything before learning one lesson.

Explore this branch

  • Database & Data Access Efficiency

    Query Optimization examines work inside and around SQL. N+1 Query Problem examines avoidable per-object round trips. Connection Pooling adds worked runtime budgets, timeout interactions and starvation diagnosis to the existing database overview.

  • Concurrency & Runtime Resource Management

    Follow asynchronous ownership, bounded workers and non-blocking I/O before measuring retained memory and CPU use. Name the runtime when a scheduling or garbage-collection detail matters; a promise is not a durable queue and a thread is not extra processor capacity.

  • Testing, Traffic Shaping & Resilience

    Load Testing checks the intended workload; Stress Testing investigates capacity boundaries and recovery. Traffic shaping decides which work may enter, while Fault Isolation limits how far resource exhaustion spreads.

  • Lifecycle & Production Observability

    Graceful Shutdown follows owned work through bounded draining. Health Checks controls whether to send traffic, wait for startup or restart. Performance Monitoring connects user-visible behavior to resource and request evidence.
